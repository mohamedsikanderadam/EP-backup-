# Emirates Paints Website – Visual Reference Summary

**Website:** https://emiratespaints.com/
**Reference recorded:** 2 – 3 September 2026
**Prepared for:** Emirates Paints

## Why we did this

Your live website is currently being shown to visitors largely from saved ("cached") copies of its pages. When we restore the website's files and database into a test environment, the result does not look the same as what visitors see today.

Before anyone repairs, updates or moves the website, we therefore recorded exactly how it looks and behaves for the public **right now**. This gives everyone an agreed picture of the website to rebuild towards, and a way to check the recovered website against it later.

## What we recorded

We visited every public page of the website the way a normal first‑time visitor would – no login, no changes, one page at a time – and saved:

- Full‑length screenshots of every page as seen on a **desktop computer, a tablet and a mobile phone**.
- The page text and layout, so wording, menus, product details and images can be compared later.
- The menus and search panel in their opened state.
- The brochures and technical data sheets that can be downloaded from the website.

| What | Amount |
|---|---|
| Web pages recorded (each on 3 devices) | 609 |
| Brochures / data sheets saved | 46 |
| Screenshots taken | over 4,200 |
| Changes made to the live website | none |

Pages behind a login, the shopping cart / checkout and account areas were intentionally not touched.

## What we noticed on the current website

These are existing issues visible to the public today. They are noted for your information only – nothing has been changed:

1. **Brochures page** (`/brochures/`) currently opens as an empty page.
2. **Product listing on mobile phones** – when filters are used, the product grid often does not appear and only the filter panel is shown.
3. **Some links lead to "page not found" or error pages** (93 addresses, for example `/visulizer`).
4. A number of product images do not load on some pages.

A full list is available on request.

## What this reference is – and is not

**It is** a faithful record of what a visitor saw on the public website during the recording period, on three device sizes. The recovered website can be compared against it page by page.

**It is not** a backup of the website's code, database or administration area, and it does not tell us whether the website was secure or fully working behind the scenes. Those points are addressed in the recovery work itself.

## Recommended next steps

1. Keep a copy of the current hosting account (files and database) before any work starts.
2. Pause content changes and automatic updates on the live website until the recovery is complete.
3. Rebuild and secure the website in a test environment, checking it against this reference.
4. Switch over to the recovered website only after you have reviewed and approved it.
